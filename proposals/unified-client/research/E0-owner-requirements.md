# E0：主人在 10-26/27 会话里给出的约束与要求（主 Agent 复盘）

本文由主 Agent 根据会话记录整理，供 `agent-parity.md` 和提示词重写使用。每条都按「Agent 自己拿主意」或「由用户决定」分类，这种分类本身也是默认 Agent 要学会的行为。日期都是 10-27，除非另有标注。

## A. 产品方向（主人的原意）

1. 要一个像 DeepSeek Harness 那样的页面：常驻 Bot 和临时会话放在同一页，网页和客户端都能访问，方便坐在电脑前操作和开发。不要再零零散散地加一个表面；状态栏、悬浮窗、网页都要合并（10-26）。
2. 产品是 yonder-harness，加上 Card 与 Net 组成的矩阵；面向不懂技术的 C 端用户。插件要克制，核心模块（包括前端）可以收回主仓。对开发者来说，「无渠道核心」仍然成立（10-26）。
3. 组网有三档：无云、自建云中转、Yonder 云。Card 是社交平台，也是最早的云。
4. 统一客户端开源，放在公开主仓，下载就能用。只有后端逻辑闭源，因为有了 AI，闭源不构成护城河。
5. Card 社交和本机控制台是同一个应用。按设备、场景、登录状态决定显示哪些功能；社交功能登录后才有。
   - Bot 模式：有特定角色的个人 Agent。
   - 控制台模式：像 WorkBuddy 那样，在本地或远端执行任务。
   - 两者联动：Bot 能看到所有工作会话，主动给建议、帮忙整理。
6. 先做远程控制，端到端加密留到以后。
7. 默认配置：
   - 本机 pi Agent 加全部本机插件都可用，用户只需要配模型。
   - 预置第一个 Bot（管家）。onboarding 由管家对照清单生成任务列表，带用户走完全部功能。
   - 本地可配置的渠道默认安装。微信、飞书、QQ、GitHub 随包提供，但默认不启用。
8. 保留一条命令安装，并在 GitHub Release 提供 Linux、macOS、Windows 安装包。产品家族名叫 Yonder，命名风格向 pi 生态看齐。
9. 社交保持现在的外观，关键流程照微信来（较难的优化先跳过）。
10. 体验要求：
    - 远程创建会话要像 pi CLI 一样顺手。
    - 桌面端像 DSH 那样极简。
    - 工作台主聊天参照 AI-Being：气泡，用户气泡上显示渠道图标。
    - 每个组件都可交互：左键、悬浮、右键、移动端长按震动。
    - 通知极简，覆盖网页、桌面、手机。
    - 会话可以右键或长按分级免打扰，同微信。
11. 一键安装、卸载、迁移都要实测，覆盖 Windows 虚拟机、Docker、macOS（本机已有安装，不能弄乱），包括已发布的客户端。客户端在后台下载更新，下载好后显示更新按钮。
12. 打包和部署全部离开 MacBook，改用 GitHub Actions：多种安装方式，桌面、iOS、安卓、Web 的 CI 都要齐全。只用确认免费的额度，并用它替代本机的重型测试。
13. 默认 Agent 一比一复刻「pi 本体加当前这组插件」的完成态，包括：
    - 提示词与上下文、todo、后台任务、子 Agent、LSP、界面信息显示。
    - compact 的节奏与频率、缓存命中（CH）控制。
    - 模型自主选择。
    - 主规划者身份。
14. Yonder 自己的提示词要重写：讲功能、原理、用户看到什么，少写规约，长度自然变短。主人认为现在文档里的很多规约在败坏 Agent 能力。
15. README 和文档体系要重构成规范的 GitHub 仓库。由 Sonnet 审读整理、删除旧文档、维护 wiki 类文档。

## B. Agent 自己拿主意的事（主人已授权，不要来问）

- 怎么理解需求、怎么定验收标准、怎么规划目标。
- 仓库操作、gh 操作、部署。
- 普通的技术选型和命名（家族名 Yonder 已定，其余由 Agent 统一）。
- Windows 测试环境用什么（Agent 判断，留意 Actions 额度）。
- 合并全部未合并的 worktree 和改动。重名和重复资源按产品方向统一重新设计。废弃方向的内容归档保存（10-27 R2）。
- 合并 pi 上游最新源码，并评估 Yonder 要跟着改什么。
- 控制并发：分析先派 DeepSeek；不要总跑全量测试，大块开发完再统一修。
- 主人的任何需求先记录，再变成 todo 项。

## C. 由用户决定、需要提问的事

- 只问产品方向、主人偏好、用户真实体验相关的问题。每个问题要单独能看懂，主人不会对照文档看。
- 问题不阻塞任务：确定的部分先做，问题放进问题队列。
- 需要主人亲手做的外部动作：Apple、npm、SignPath 账号，创建 GitHub App，组织改名，远端分支删除（被 Safety Net 拦截），以及凭据。

## D. 协作与成本（主人给的执行规则）

- 主 Agent 只做规划、分派、审核、需求梳理和文档整理。有些任务要把主人原话原封不动地传达给执行者。需要读主 Agent 上下文之外的文档时，交给 Sonnet。
- 模型分工（价格均为输出价，元/百万 token）：

  | 模型 | 输出价 | 角色 |
  |---|---|---|
  | DeepSeek v4.1 flash | 免费 | 首选执行 |
  | GLM-5.3 flash | ≈0.6 | |
  | Claude Haiku 5.5 | ≈1 | |
  | GPT-6.1 terra | ≈2 | 较难的执行 |
  | Claude Sonnet 5.5 | ≈6 | 设计执行、文档整理 |
  | Claude Opus 5.5 | ≈12 | 规划 |

  这些价格是主人临时给的资料，产品里要换成来自数据源的自动信息。
- 用好 codegraph 省 token。
- 分析完成后，按之前的风格提问敲定方案，再继续执行。

## E. 对默认 Agent 设计的含义

- B 类事项写进主规划者身份，作为「替用户省心」的默认行为。C 类事项写成「什么时候该问用户、怎么问」。两者都要从功能和原理讲起，不写成条款清单。
- D 类事项本身就是产品功能：模型目录与选型、子 Agent 分派、成本可见性（底栏用量、缓存命中率）、todo 树、后台任务、问题队列。
