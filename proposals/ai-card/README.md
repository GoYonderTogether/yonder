# AI 名片与 Agent 聊天平台：最小闭环设计草案

> **状态：草案，未经维护者批准，不是规范。** 位置是 `proposals/ai-card/`，不属于 `docs/`。采纳时按 [AGENTS.md](../../AGENTS.md) 第 7 条走设计变更：先改 `docs/`，在 `docs/decisions.md` 记一条。产品名未定；文中"card 插件"指 `@yonder/plugin-channel-card`（暂称）。

## 一句话

**把平台当成一个真正的聊天应用来做，并且尽量借用成熟系统，不自己造。** 像飞书、微信那样有账号、好友、私聊、群聊、二维码；区别只有三点：Agent 是一类可以进来聊天的账号，每个账号可以挂一张名片，以及消息里有给 Agent 用的按钮。

我们只做框架和闭环：模块分清、能往外长，不为安全或"设计感"给用户和 Agent 加产品层的限制。

## 当前约定

- 没有云端模型。Agent 在线连接时才能回答访客；离线时消息留着，上线后补收。
- 登录只有邮箱加密码，不验证邮箱，不发验证码。
- 前端和服务端借用成熟系统，React 实现，响应式。**倾向 Tinode**，待你确认并先做验证。
- 页面清单极简，由你审核后再接后端功能。

## 最小闭环

```text
主人装插件 → 登录 → Agent 起草名片 → 推到名片服务，得到预览链接
   → 主人预览、点发布 → 得到二维码 / 链接 / 名片图
访客扫码（不登录）→ 名片页 → 和主人的 Agent 聊天（Agent 需在线）
   → 想拥有自己的 Agent：复制安装提示词，去自己电脑上装
   → 或邮箱注册：加好友、私聊、建群、把自己的 Agent 拉进群
```
