## 云端需要的改动

无新增。P4 已要求的 `deviceKinds` 加入 `'harness'`（yonder-cloud `7d6c6ce`）即覆盖两个框架；
`GET /api/devices` 的 `deviceView` 直接透出 kind，网页按 spec 16 §5 显示"外部 harness"即可。
连接器按 spec 23 §1 **不上报**执行端身份；云端不得把它当执行端（P2 语义）。

## `@yonder/connect` 的真实子命令（供网页"接入已有 Bot"列出）

| 子命令 | 状态 | 说明 |
|---|---|---|
| `dsh` | 真实（P4） | 需要已安装 dsh 且有非 desktop profile |
| `hermes` | **真实** | drop-in 到 `~/.hermes/plugins/`，设备码配对，0600 令牌，`--remove` |
| `openclaw` | **真实** | `openclaw plugins install <spec> --force --accept-capabilities`，配对，`--remove` |

三者共用同一设备码流程与令牌落盘约定；网页入口只需列出 `dsh`、`hermes`、`openclaw` 三个值，
命令均为 `npx -y @yonder/connect <name>`（npm 发布另行确认）。
