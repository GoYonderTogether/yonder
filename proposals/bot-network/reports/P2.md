## 偏离与判断

1. **允许表路径**按裁决用 `/api/bots/:id/devices`，取代 19 §9 原写的 `/api/bot-devices`；`GET` 额外返回 `devices`（含在线状态），便于 P3 直接渲染。
2. **grant 撤销的优先级**：裁决要求撤销在下一次调用生效。实现中发现“发现刷新会把刚撤销的授权签回来”，因此在执行端加“被主人撤销的 Bot 不再接受重复介绍，直到云端重述允许表”。这是规范新增语义，已写入 19 §10；不做这一步就没有真正实现裁决。
3. **控制端身份按账号一份**（设备 Harness 用 `controller-key.pem`，云端 worker 每账号一份），不按 Bot 分发密钥；“哪个 Bot”由 grant 的 `botId` 区分。这样同一台设备上的多个 Bot 不因密钥轮换互相失效。
4. **设备凭据**新增两个只读接口 `GET /api/device/devices`、`GET /api/device/agents`；`GET /api/devices` 仍是人类接口。插件原先误用它，是被真实进程验收挡下的。
5. **默认发行包含 `devices`**：规范要求“不自动安装、不扩大设备集”；插件加载本身不注册设备、不签 grant，因此满足规范，同时消除远程资源会话缺工具的静默失败（改为真实错误）。
6. **安装器 workspace 启动器**只写 `yonder-executor`/`yonder-clipboard`/`yonder-qq` 三个已声明 `bin` 的包；未改 npm 发布。
7. **`devices_operation` 保留**（裁决 6）。

## P3（网页）要消费的接口形状

所有路径相对云端 origin；错误统一 `{error: string}`，HTTP 状态与错误码一致。未登录 401 `unauthorized`；非主人 403 `forbidden`；他人或不存在的对象 404 `not_found`（不泄露存在性）。

### 设备列表（已有，P3 扩展显示）

`GET /api/devices` → `[{id, code?, name, kind:'laptop'|'desktop'|'server'|'cloud'|'harness', online, workProtocol?, executor?:{deviceId,publicKey}}]`

`executor` 只在该设备执行端自报过身份时存在；P3 用它显示“执行端已登记/未登记”。

### 设备的 grant（19 §10）

`GET /api/devices/:id/grants`

```json
{ "observed": true,
  "grants": [{ "grantId": "uuid", "principalId": "64-hex", "botId": "uuid|null",
               "botLabel": "设备 Bot|null", "source": "cloud|manual",
               "capabilities": ["read","write"],
               "targetIds": ["host:filesystem"], "readRoots": ["/abs"], "writeRoots": ["/abs"],
               "revision": 1, "issuedAt": "ISO", "expiresAt": "ISO", "revokedAt": "ISO|null" }] }
```

- `observed:false` 表示该设备从未上报过（还没连收件箱），与“有设备但零授权”不同。
- `botLabel` 优先取云端 Bot 账号名，其次控制端自报名，再退化为 null。

`DELETE /api/devices/:id/grants/:grantId` → `{revoked:true, pending:boolean}`

- `pending:true`＝设备离线，撤销已排队，重连后送达；UI 应显示“等待设备上线”而不是“已生效”。
- 已撤销或不存在 404 `not_found`；重复撤销幂等（仍 200）。

### Bot 可操作的设备（19 §9）

`GET /api/bots/:id/devices`

```json
{ "botId": "uuid", "mode": "all|selected",
  "devices": [{ "id": "uuid", "code": "ABC123", "name": "MacBook", "kind": "laptop", "online": true }],
  "allowed": ["uuid"] }
```

- `mode:"all"`：`allowed` 是当前账号全部有有效设备会话的设备（新绑定设备自动进入）。
- `mode:"selected"`：`allowed` 是收窄后的列表，可以是空数组（＝不允许任何设备）。

`PUT /api/bots/:id/devices` 正文 `{mode:"all"}` 或 `{mode:"selected", devices:[uuid]}` → 同上形状。

- 任一设备 ID 不属于本账号，或被写者不是 Bot 主人：404 `not_found`，整条不写入。
- 空数组是合法的“不允许任何设备”，不要当成“未配置”。

### 设备拉取自身身份（连接器/诊断用）

`GET /api/device/devices`（需设备 bearer token）→ `{devices:[{id,name,kind,online,executor?:{deviceId,publicKey}}]}`

`GET /api/device/agents`（需设备 bearer token）→ `[{key, accountId, name}]`

### 云端会话/工作台相关（未改形状）

- `POST /api/devices/:id/relay` 正文 `{frame}`：控制器专用，网页端**不**调用（网页是 human 会话）。
- `GET /api/devices/:id/agents`、`POST /api/devices/:id/work/rpc/:method`、`WS /ws/work?device=`：与 P1 相同。

### P3 不应做的事

- 不在网页里签 grant、不在前端计算能力交集；`allowed` 与 `grants` 都是回读，不是授权来源。
- 不把 `pending` 撤销显示为已生效；不把 `observed:false` 显示成“无授权”。
- 不允许模型或 Bot 自己的工具调用上述写接口（需要 human 会话）。
