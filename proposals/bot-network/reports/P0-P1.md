## 规范问题（未自行决定，交维护者）

1. **规范编号**：22 已被占用，连接器规范编为 23（见上）。若维护者希望保留 22，需要先给 shared-bot-core 改号，会牵动 16 与 19 的既有引用。
2. **`kind='harness'` 的落库方式**：`devices.kind` 有 CHECK 约束。规范写了"按现有 `devices_kind_check` 方式放宽允许集"，但没有指定是新增迁移还是复用 `cloud` 的既有做法；实施时需要一条前向迁移，具体编号交维护者。
3. **允许表的 HTTP 路径**：规范写成 `/api/bot-devices`，与现有 `/api/devices`、`/api/runtimes` 同风格；计划只说"HTTP API shape at the level the spec style uses"，没有给路径。若维护者倾向挂在 `/api/bots/:id/devices`，改规范即可，语义不变。
4. **云端介绍配对的传输**：规范只要求"走签名封套与 challenge-response"，没有规定新增哪个 RPC 或帧。实现时需要定这是执行端 RPC、Card 帧还是 work 帧；这里涉及外部可见协议，属设计变更，未自行补。
5. **`grants.list` 的默认可见范围**：规范写"本设备发给当前已配对 principal 的 grant 摘要"，没有说主人是否应能看到**其他** principal（例如同一账号另一台控制端）的 grant。v1 按最小可见性只给本人；若要"网页能看到这台设备给过哪些能力（给所有 Bot）"，需要设备端另开主人视图，未设计。
6. **`devices_operation` 的规范地位**：research/01 把它列为"代码超出规范、需维护者裁决"。本轮按任务书把它补进 18 与 plugins.md，等于默认合法化。如果维护者本意是移除该工具，本轮文档改动需要回退。
