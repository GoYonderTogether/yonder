# Yonder 插件调试

用户要求检查插件、演示能力或复现问题时，选择能证明目标的最短线路。复用现有渠道、CLI/MCP、原生转录与日志，不创建调试服务或第二套任务/记录系统。

## 选择与执行

1. 用 `yonder version --json`、`yonder inspect --json` 确认实际版本、home、目标agent/profile和有效权限。按实际插件注册/工具schema选择操作；skill是指导，tool是调用，plugin是能力来源，三者分别核对。当前入口无exec时使用已提供的工具，或让外部操作者执行CLI；不为调试提权。
2. 从用户指定范围选用例，列明操作、成功条件和允许的外部影响。没有指定时先做一条只读短任务，不自动调用所有工具。测试标识放正文和产物名，沿用真实渠道来源，不伪造账号或原生消息ID。
3. 从要验证的入口提交：飞书接收/绑定必须有真实飞书输入；从CLI/MCP发任务再回飞书只证明这条控制链与飞书出口。普通批量演示可一次下达一组明确操作；独立插件可拆成短任务，不要求塞进一个长run。
4. 执行者调用真实工具并展示获准产物；观察者在外部收集进度及终态。执行者不等待自己的run.end，也不关闭承载自身运行的会话；终态查询和会话收尾由外部操作者完成。观察断开不等于任务中止，不重复提交未知结果的副作用。失败后保留原错误，继续不依赖它的用例；重试只用于核验新假设。

正常链、时间窗口或故障的具体做法，按需读取 [场景线路](references/scenarios.md)。

## 查证已有记录

```bash
yonder version --json
yonder service info --json
yonder sessions list --json
yonder sessions show <session-id> --json
yonder events --type run.end --since <开始时间> --json
yonder events --type message.out --since <开始时间> --json
```

服务ready、PID及运行commit来自 `yonder service info --json`；没有 `yonder status` 顶层命令。模型不确定命令语法时先查 `yonder help` / 已有文档，不猜子命令。

先检查目标home；隔离环境的每条命令都显式传 `--home <隔离home>`，不让自动发现连接正式服务。开始时间使用带时区的ISO时间。

外部MCP入口（默认插件ID为channel-mcp；实际名称以工具列表为准）：

- `channel-mcp_events_emit`：按绑定接纳输入，立即返回事件；`events_ask`等待运行结果。
- `channel-mcp_sessions_open/submit`：创建/驱动preset任务，不能绕过绑定唤醒常驻agent。
- `channel-mcp_sessions_watch`：有界观察；断开只解除观察。观察结束或截断后查询持久记录，不另发任务。
- `channel-mcp_events_query`：用after续读事件；`sessions_transcript`用from/limit续读转录。

CLI的sessions show默认只取一页，不能据此声称没有后续调用；需要完整转录时用现有MCP分页接口。按原始输入ID、事件routes、会话及run.end.inputs建立关联，不只按时间、最后一条记录或模型自述认领结果。一个run可能消费多条输入。

当前转录接口包含工具名、参数及文本化结果，但没有完整暴露所有结构化回执、调用关联字段和图片块；watch也是有界窗口。证据不足时补查现有原生产物或脱敏日志，明确缺口，不杜撰调用成功率或新增追踪系统。不要输出凭据、无关聊天或完整私人配置。

## 判定与结束

每项只记录必要事实：操作、入口/版本、输入事件与会话、实际工具名及脱敏参数、返回/错误、产物或原生消息ID、结论。报告保存在用户指定位置，未指定时保存在本次隔离目录；向请求者简短汇报。

- **通过**：该项成功条件有实际结果；区分源码插件调用、安装版模型运行、平台投递与客户端可见。
- **失败**：保留原错误和阶段；结果不确定时明确标记，核对实际副作用后再决定下一步。
- **未测**：缺权限、环境、客户端观察或用户主动跳过；不拿其他项成功抵扣。

执行者不能确认外部入口时写“待外部核对”，不要推断自己是否由preset/渠道驱动；观察者以原始输入和会话事实修正口头报告。

不把读到skill、工具注册、最终口头回复或发送返回ID当成整项能力通过。图片/音视频真正可看可播，需要客户端检查或用户反馈。

达到本次成功条件或遇到具体阻塞就停止；不追加全功能矩阵。清理本次自建会话、浏览器资源及临时服务，保留失败证据；不删除原有历史、不停止正式服务，不顺带修代码、安装、推送或发布。
