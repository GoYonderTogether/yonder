# 场景线路

只选择当前目标需要的一条。沿用用户已经批准的账号、会话、操作范围和环境；skill本身不授予新增外部权限。

## 1. 真实渠道短任务

适用：确认模型能选中skill、发现工具、执行操作并交回结果。

可向目标AI发送：

> 使用yonder-plugin-debug。在本次指定测试会话验证列出的操作；先读取相关skill，再调用真实工具。逐项给出工具名、结果、产物或原生消息ID。保留失败，继续独立项，不修改配置或扩展范围。

只读首轮可检查插件状态、读取获准测试文件/会话。要验证发送、上传、评论等写操作，使用已获准的目标与本次文件；没有授权就先报告缺项。

核对：原始输入→绑定/来源/权限→实际工具调用与结果→run.end→需要时核对投递与客户端。CLI/MCP成功不能抵扣真实飞书接收。只需演示时复用已安装能力，不再搭一套开发服务。

## 2. 可重复的小脚本

适用：相同操作序列反复执行，或需要批量汇总原生结果。

优先复用项目已有检查或脚本；确有重复才把固定提交/查询步骤写成一个短脚本，调用现有接口并保留JSON输入、结果和本次标识。采用有限等待，结束后取持久记录；不靠无限轮询或延长产品超时制造通过。

脚本直接调用插件只证明插件操作；经安装版AI执行才覆盖模型及核心接线。报告分别注明。无需模型的文件/格式问题直接检查，无需每次调用LLM。

## 3. 工具执行期间插话 / 取消

适用：必须证明某输入发生在另一个操作执行期间，人工抢时机不稳定。

在隔离目录使用一个有界工具操作：到达等待点后写入ready标记，等release标记或短截止。外部操作者提前订阅观察，确认实际工具开始并到达ready，再从目标渠道发送B，确认接纳后释放等待点。取消用例则在ready后从外部发abort，不让被取消的AI负责报告自己的终态。

保存工具开始、B的原生发送/接纳、工具结束、B在转录中的位置及run.end.inputs。判定依据是原生时序；仅在背景准备时接纳B不能称为“工具执行中插话”。超时保留证据并停止，不用增加sleep反复碰运气。真实渠道投递延迟仍可能导致未命中窗口，如实记录。

## 4. 恢复 / 去重 / 权限

适用：正常短任务无法覆盖的执行边界；只在本次确实要求时运行。

- 断连恢复：为测试实例和获准会话记录起始游标；只断开该实例的连接，在指定会话发带标识的消息，再恢复。按原生ID核对接纳、run输入与投递次数。不切整机网络、不停止正式常驻。停进程再启动与真实网络断连是不同证据。
- 重启恢复：在已确认的阶段停止隔离实例，随后用同一测试home重启。核对待处理输入、终态和外部副作用，不修改pi转录或业务事件来伪造恢复。
- 权限：通过独立测试账号/profile及实际绑定调用同一操作，检查预期允许/拒绝和外部实际影响。主人成功不能证明访客受限，不在正式配置上临时放大权限。

无隔离实例、测试账号或必要权限时报告未测；不要为了补齐清单改造产品架构。

## 5. 测试材料和环境

可在隔离目录创建明确标识的文本、图片等测试材料，或使用授权的专用群、临时仓库及测试账号。它们是测试输入，不是产品示例人设或虚构业务事实。模型测试使用真实模型，平台接入使用真实平台；本地重放只证明对应解析/状态逻辑，不能冒充平台验收。

记录版本/commit、目标home、profile/能力、文件及触发顺序，足以再次执行即可。隔离home、端口/socket和前台服务不得替换正式launchd或复用正式数据目录；登录沿现有授权方式配置，不拷贝正式凭据。外部材料由本次操作者提供或经授权读取，不增加供应商或测试平台。

播放器、视觉布局、首次登录/扩展授权、系统注销登录、自启等，需要客户端或系统层观察；工具返回成功不能替代。用户已决定跳过的项保持跳过，等实际反馈再复现。
