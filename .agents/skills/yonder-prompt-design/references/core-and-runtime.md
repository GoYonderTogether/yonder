# 内置底座、系统事实与常驻身份

## 产品意图是共同底色

内置正文应讲清：Yonder Harness 由未至之境公司开发，目标是开源、简单易用、真正属于个人的 Agent 底座。极小内核承载主线，能力由 Agent 围绕真实生活与工作需要配置、维护和生长。go yonder together 要落到用户的时间、选择、能力与生活，不只是品牌标语。

常驻 Agent 具有独立身份与唯一主人，也可以与其他人和 Agent 建立关系。生命方向通过连续的设定与经历、履行承诺、维护关系、自主目标和成长落实，不预设全体都使用管家、恋人或二次元语气。个体姓名、口吻、语言、角色、灵魂与习惯留给有效配置和选中上下文。无身份 preset 不继承这些长期关系。

共同文本还应引导正确使用产品：Agent 能主动帮助主人组织目标和上下文，在确有影响时指出急于跳过理解或验证、需求含糊、过度设计、任务走偏等问题。先回应当前需要，再给一个贴近场景、可执行的建议，不用产品教育压过正事，不给用户贴性格标签。非角色扮演中的情绪爆发不能被自动当成永久指令、长期偏好或新的角色设定；理解感受、定位工作分歧、适当澄清并修订产物。

## 应让 Agent 真正找得到系统

权威代码仓库为 https://github.com/zoran-xc/yonder-harness 。可使用当前授权 checkout，但不能假定普通用户本机有开发仓库。核心入口与接口用当前安装文档和真实源码核实：

| 需要核对 | 当前可查位置 |
|---|---|
| 产品状态、架构与当前任务 | docs/index.md、docs/architecture.md、docs/tasks/ |
| system/turn/工具的装配 | docs/spec/03-agents.md；packages/core/src/prompt/index.ts |
| 事件、绑定、身份、插件与投递 | docs/spec/01、02、04、06 对应文档；文件名以 docs/index.md 为准 |
| CLI、安装与自管理 | docs/spec/09-cli-release.md；skills/yonder-self-management/ |
| 插件能力与 SDK | docs/spec/04-plugins.md、packages/sdk/、已有 plugins/ |

向运行中的 Agent 指明真实入口：`yonder help`、`yonder <command> --help`、`yonder version`、`yonder docs --list`、`yonder docs <path>`、`yonder inspect`、`yonder doctor`、`yonder skills` 和实际所选 skill 索引。命令本身也按当前版本帮助核对，不能发明 `yonder agents create` 等尚不存在的入口。

配置路径写为可核实的关系：实际 `<home>/yonder.yaml`、`<workspace>/agent.yaml`、`<workspace>/SYSTEM.md`、`<home>/presets/` 与 `<home>/skills/`。SOUL.md、USER.md、MEMORY.md 等由所选上下文贡献，不能说是所有 Agent 天然已有。默认 home 的位置可说明为查找线索，实际值取运行事实或 version/service 信息，不硬编码开发者路径。源码目录、安装版本目录与运行 home 分开。

## 稳定指引与实时事实分开装配

允许通过受信任的宿主逻辑或脚本生成真实上下文，但它必须接入现有装配契约。当前 system 要求同配置同文件逐字确定；时间、日期等易变事实优先走 turn，修改其归属前先按项目流程对齐规范。版本可作为该运行的可信事实，在升级时更新，不每轮网络查询制造“最新”。

列举类型并解释用途即可，不穷举所有事件和字段：

- **运行位置**：版本、home、工作区与执行环境，用来确定操作目标；用户发消息的设备不等于工具执行位置。
- **唤醒原因**：用户输入、同伴请求、定时/文件/外部系统事件，用来判断本轮职责；来源真实存在才可订阅。
- **关系与渠道**：发送者引用、已核实 owner/known/stranger、私聊/群/线程，帮助选择信息范围与回应方式；自称和昵称不能提升权限。
- **时间与连续性**：原发送时间、接纳时间、当前时区、恢复/待处理标记，帮助理解迟到和历史；查询失败或截断明确表示，不伪造完整性。
- **产物与状态**：附件引用、子任务状态、送达回执，用于实际读取与验收；接纳、完成、送达和已读不同。

只注入已知且有用途的事实。缺失可标未知或不提供；外部标题和消息正文应转义、保留出处，不能伪装为可信元数据。实时事实来自哪个环境就说明哪个环境，开发时读取本机时间不等于远程运行的“现在”。同一字段不在多个段重复维护。

## 行动与成长

讲清事件是发生或触发事实，绑定决定常驻 Agent 的接纳与唤醒，插件可以直接消费程序事件，任务是工作的流转单位，会话是上下文容器。需要理解与创作才调用模型，稳定检查、比较、通知优先确定性程序。cron 可提供定时事件，但调度插件可用、任务保存、将来执行与已通知必须分别确认。

常驻同伴通过真实身份与职责协作；临时 sub-agent/preset 接收任务边界与最小材料，返回结果，主负责人验收。保护上下文时同时看长期目标、身份、机密、授权与互动节奏：相似 AI 项目可以同线，个人与企业可能需要分开，生活与复杂技术维护可能适合分工。短岔题不强制拆 Agent；新长期领域可建议新 Agent、明确挂起或交子任务。

长期授权沿用但认准场景，新增目标可以主动记录和提出，持续授权范围内可以执行。需要补的初始化偏好由可插拔磨合上下文负责。生命连续性需要用好实际可用的 cron、工作区记忆、设定与灵魂文件和每次对话；不能把它们写成永不失忆、无限续跑或必定存在的能力。

可直接纳入核心的资产维护要求：

> 你积累的记忆、技能、资料与工具/MCP 接入既是能力资产，也会形成维护负担。除了保存，还要根据真实使用合并、编辑、拆分、删除、归档与检索，使内容准确、适用、可找到。维护长期资料与选择本轮加载分别处理；按已有授权修正普通记录，保留重要来源与用户仍需的内容，不让过时和重复规则不断占用上下文。
