# 可插拔的认识与磨合上下文

## 设计目标与参考

用户已确认：借鉴 BOOTSTRAP，但不要求首次交谈结束即删除；随实际相处补足设定与使用偏好，经过磨合后自查收尾。初始化引导必须属于可插拔插件，而不是内核硬编码流程。

参考本机固定版本 OpenClaw `docs/reference/templates/BOOTSTRAP.md` 与 `docs/start/bootstrapping.md`；在线入口为 https://docs.openclaw.ai/start/bootstrapping 和 https://github.com/openclaw/openclaw/blob/main/docs/reference/templates/BOOTSTRAP.md 。本轮 2026-10-19 已核对官方页面；上游可变化，后续有需要再核对版本。借鉴任务优先、渐进确认与持久化，Yonder 的完成时机和插件归属按自己的要求设计，不复制上游命令、头像流程或人设。

## 边界与形态

建议使用可选上下文插件，工作文件暂名 `BECOMING.md`，完整起始正文在 [模板](../assets/BECOMING.md)。名字是候选，不是已存在的插件注册名。它服务有身份与工作区的常驻 Agent；无身份任务预设不加载，不在未选中的 Agent 中创建文件。

插件启用与该 Agent 显式选择上下文是两件事。内容只在自己的作用域按需要提供；群聊和陌生人不会因看到清单获得修改主人偏好、身份与自治范围的权力。没有写权限时可以询问和提出修改，不能声称已经保存。

## 清单怎样在生活中完成

用户有真实任务先完成任务。涉及某个未确定偏好时自然问最相关的一项，不逐条盘问，不阻塞已有工作。不相关项可以留到后续；允许“暂不设定”和“不再询问”。用户已经明确的内容直接归入正确记录，不再问一次。

每项区分待确认、已确认、延期与跳过，并保留必要的适用范围或对应文件位置。清单追踪磨合进展，身份/灵魂/偏好/授权/项目状态应写入各自真实载体，不让清单变成永久万能记忆。

主题覆盖：相互称呼与身份、帮助的长期方向、生活/项目分工、偏好与禁忌、交流与提醒方式、自治授权及撤回、记忆整理、已有渠道和设备、当前缺失能力。不是必须把所有私密信息填满；日期或轮次数不是完成标准。

## 退出、删除与重新开启

关键设定已写到真实目标并被后续相关工作使用，重要分歧已解决或明确延期/跳过，不再需要初始清单时，Agent 可以在授权内自查归档或删除临时文件。保留必要完成事实，不能因用户没回答或某个 USER.md 非空就宣告磨合完成。

移除活动清单前确认长期内容没有只存在于该清单。完成后不再把清单常驻加载；禁用插件立即停止其上下文注入，按现有重载/重启契约生效，保留用户的长期资料。重新启用默认沿用完成事实，不重新盘问；只有用户重开或明确重建时再次进入。

当前 `scaffoldWorkspace` 会为选中的 `files.scaffold` 补缺文件。如果简单把清单声明为始终 scaffold，删除后下次准备工作区可能重建，造成反复初始化。实施时沿用现有插件数据或已归档标记保存完成事实，并让创建策略先查它；不能只删文件而无视这个调用链，也不能为此新造全局生命周期数据库。具体钩子与创建入口先核对 SDK；文案不能声称已有专用 slot。

这是插件设计与可用正文模板，尚未实现。真正接入时要核对新 Agent、既有 Agent、禁用/重启/重新启用、只读、部分完成和收尾后不重建；没有执行这些检查就不能说插件可用。
