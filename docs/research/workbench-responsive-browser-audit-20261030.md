## 判断

实际确认三个可复现的状态/布局问题，以及一个断点口径差异：

1. **设置页收起列表后无恢复入口。** `1440 × 844` CSS 像素，打开 `/work/settings`，键盘激活「收起工作列表」后，aside 数量为 0，页面中不再有「展开工作列表」按钮。见 `/tmp/yonder-responsive-evidence/settings-1440-collapsed.png`。
2. **仅工作列表中再次打开当前任务不会返回内容。** `1440 × 844`，打开 `/work/161323` 并选择「仅工作列表」，键盘激活当前任务后 URL 变为带设备的 `/work/device/.../161323`，选择仍为 `list`，显示仍停留列表。见 `/tmp/yonder-responsive-evidence/current-task-list-1440.png`。
3. **平板同时展开列表和渠道时会把会话挤窄。** `768 × 844`，在 `/work/2` 自动模式中打开「渠道与子会话」，再展开工作列表：列表宽 320、渠道面板宽 300，中间会话剩约 148 CSS 像素。页面根节点横向溢出为 0，但这不是内容可读性的证明。见 `/tmp/yonder-responsive-evidence/tablet-768-list-channels.png`；打开渠道未展开列表的对照为 `/tmp/yonder-responsive-evidence/tablet-768-channels.png`。
4. **返回会话时“仅右栏”选择丢失。** `768 × 844`，`/work/2` 选择「仅右栏」，展开已完成子任务并进入其中一个真实子会话，再执行浏览器返回，回到 `/work/2` 后选择为 `content`，此时 `rail` 选项已可选。返回命令自身等待超时后会话恢复，随后读取到该结果；不能仅凭观察断定具体内部原因。

另在 **1024 CSS 像素**观察到外层主导航已经是宽 64 的桌面侧栏，而工作台仍使用平板分支；1025 时工作台切换桌面分支。这与外层 CSS 和工作台 JS 的阈值口径有关，是已观察到的断点差异，不单凭该差异认定遮挡或功能故障。见 `/tmp/yonder-responsive-evidence/width-1024-auto.png`。
