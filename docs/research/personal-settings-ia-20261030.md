# 个人页信息架构方案（2026-10-30，未实施）

目标是让主人从“我要管理什么”找到入口，压缩重复的首屏展示；保留真实对象、现有路由与权限，不新增虚构云能力。此文是方案，不代表界面已重排。

## 现有事实与重复

| 当前入口 | 已有能力与作用范围 | 发现 |
| --- | --- | --- |
| 个人抽屉 | 个人资料与名片、我的发布、市场收藏、添加设备、设置与账号安全 | 是跨模块入口；同时列出内容与设置快捷项 |
| `/me` | 身份资料、Bot 的名片、我的名片、收藏的名片、我的市场、我的 Bot、渠道接入说明、设备、设置 | 一页既有个人资料，又展示 Bot 管理、市场和设备接入；Bot 的名片与我的 Bot 分开呈现同一类主体；设备入口也在抽屉 |
| `/me/settings` | 账号与安全、通知、设备、渠道、社交设置、关于 | 新的统一多层设置入口；实际设备相关子页先选账号绑定且支持工作台的在线设备 |
| 账号与安全 | 昵称、手机号/邮箱绑定或换绑、退出 | 账号范围；换绑会撤销全部会话，保留确认及重新登录提示 |
| 通知 | 设备节点通知开关；浏览器本机震动和预览；会话级另在消息列表 | 不同作用域需在同一页明确标注，不可假称统一跨设备 |
| 设备/渠道/社交 | 真实账号设备状态；选中设备上的渠道列表与登录、Bot 的群设置；本机模式另有节点地址 | 离线/未支持不等于删除；渠道授权仅由主人主动操作，普通账号不得获得其他设备权限 |
| 关于 | 本机可见版本/更新；云设置提示本机查看 | 不虚构设备版本和可远程更新能力 |
| `/work/settings` | 旧链接兼容至统一设置 | 保留历史入口和返回路径，不在工作内容菜单增第二个设置页 |

## 建议的用户目标分组

1. **我的身份**：保留真实头像、名称和名片入口，资料编辑与账号昵称的关系明确；收藏的名片作为“名片”内部入口，避免首页展开完整管理块。
2. **我的 Bot**：将当前“Bot 的名片”和“我的 Bot”收为一个 Bot 管理入口或同一区块；每个真实 Bot 展示头像、名称、可用状态，进入该 Bot 再编辑其名片和可见性。继续按真实 actor/设备映射，不能用名字猜身份；失败与空状态分开。
3. **我的市场**：把发布、收藏、统计归到现有市场中心入口；个人页只留真实数量或入口，避免复制市场页面。
4. **设备与渠道**：提供一个“设备与渠道”入口，以真实已绑定设备列表为第一层，选择设备后进入该设备的渠道、连接状态及可用操作；无设备提供现有添加设备入口，离线显示离线，旧版本显示不支持。保留本机节点与云设备不同权限和状态，渠道只有确有接口和权限时显示状态/登录，旧命令说明只能标明适用条件，不能假称已接入。
5. **设置与安全**：账号、安全、通知、社交设置、关于沿统一设置分层；设备内配置从设备详情进入或从设置导向同一页面，不复制第二套编辑器。账号安全与设备解绑继续使用现有明确确认。

## 最小交互草图

```text
个人
  身份与名片 → 资料 / 我的名片 / 收藏名片
  我的 Bot → 真实 Bot 列表 → 该 Bot 资料与名片
  我的市场 → 发布 / 收藏 / 统计
  设备与渠道 → 选择真实设备 → 状态 / 渠道与设备设置
  设置与安全 → 账号 / 通知 / 社交 / 关于
```

个人抽屉是快捷导航，个人页是同一信息架构的完整入口，不复制每个详情页的管理表单。首屏优先身份和四个清楚入口；具体数据不应因压缩而被删除。访客只显示其真实可用能力和注册引导。

## 实施前需确认及验收

- 统一设置当前实现和各入口先完成真实浏览器验收；本方案尚未实施。
- 先核对设备列表是否已有足够的真实渠道状态及按设备选择能力；若没有，显示明确的不可用或进入现有接入路径，不新增虚构状态或 API。
- 与主人确认个人页是否仍需首屏看到 Bot、名片、市场的摘要；不能把入口压缩误当作删除能力。
- 浅暗、手机/平板/桌面、无设备/离线/旧版/多设备/访客、权限错误、旧链接和子页返回分别核验；绑定、换绑、渠道登录和退出不作为只读验收操作。
