# Harness 自配置闭环修复

用户本轮要求从共享根因修复，使主人说出需求后，Agent 能配置、热重载、验证并交付，安排子 Agent 落地；不是逐 Bot 改 persona。实施范围为仓库源码、规范、随包指引与验证；正式 home、安装、公开发布分别验收，本次不以源码完成冒充上线。

## 完整行为链

复用 YAML、management/config/social API、pi-durable、事件和投递回执，不另建配置 DSL、审批平台、自动纠错 Agent 或任务/转录数据库。

1. 核对真实主人输入、目标home/版本、Agent、渠道/群及profile，沿用同对象/任务的授权。共享main保留历史，但原生inbox一次执行一个可信来源组：同源可steer，异源持久排后续轮次；parent请求与内部续办回溯原来源，显式interrupt保持原意。来源键不授权、不复制群历史。
2. 查模型目录、实际binding/profile、工具插件、已有会话和参与策略。明确普通批次配置请求沿现有social.update候选预检完整依赖，缺件一次返回精确对象、字段和现有agents.show/validate/update修复入口；未知不当缺失，不暗改共享profile。身份、上下文、能力、模型、调度、投递分别定位。
3. 形成最小局部候选，识别共享 profile 的影响范围，用现有 validate 做完整候选校验，不保存已知不可运行的路由。
4. 用 update/apply、既有锁和原子写入，等待 reload 接纳；失败恢复本次写入，不覆盖并发修改，恢复失败明确报告。
5. 读回有效配置与路由，核对新入站、run.end和成功message.out。明确batch.run=true的合格普通输入按既有限制进入模型，发给别人或兄弟先答不能推进为已处理；公开发言仍由模型结合最新群上下文决定。没有新消息时明确端到端未测，出站成功不证明入站。
6. 交付改变、范围、有效配置、运行/送达证据和未测项。后台工作沿结果通知或 task_continue 续办，不以口头承诺结束。

| 用户需求 | Agent 与宿主的行为 |
|---|---|
| 私聊用某模型，群聊用另一模型 | 分别定位既有 profile，仅改相关模型/必要 fallback，保留其他字段。配置首选与实际 fallback 模型分开 |
| 负责工作群，消息都看、按需说 | 同 Agent、独立群上下文，必要执行沿 parent_ask；接收、唤醒、发言分开，节奏取实际配置，不强加新默认 |
| 这个群先别说话 | 复用 social_group_mode_set/social.update 设置 mute 并读回；复用已有发送控制，不扩大自然语言正则，不承诺撤回已送达消息 |
| 读群里的附件后办理 | 使用当前来源 message/index 和 conversation_attachment_read；必要时转交原请求，不要求用户搬运已收到材料 |

用户已确认“同一个Agent办事，群历史独立”；验收user message保持原话，不把这一实现解释附加进去。“同 Agent 接管”不自动公开私人 main conversation。用户明确要求同一份上下文时报告现有支持边界，不暗换含义或保存运行时必拒绝的绑定。模型/工具独立选择不要求合并上下文；既有会话 profile 不能偷偷替换。

## A 配置与路由契约

- 管理写入、watcher 与启动复用既有可接纳性校验，群→私人main、缺插件和可确定的打开会话profile冲突仍按原规则拒绝。本轮新增的批次消费者完整性检查在候选入口对可证明的群链严格执行；启动保留旧home可运行与自修入口，真实入站对缺链失败关闭并提供inspect诊断。静态未知kind不猜群类型。错误带字段/绑定与真实缺件，不自动扩大权限或更换目标。
- 管理写入等待同步 reload，返回 saved/accepted/restartRequired 和可核对版本；accepted 仅服务接纳。失败恢复本次文件且报告恢复状态。
- config.get/update 支持可选既有 profile；省略保持 defaultProfile。CLI agents show/validate/update 继续负责完整配置，不新增工具平台。
- social.inspect 去掉占位，提供真实策略、绑定/profile、历史入站路由及缺口，标明历史事实与当前预测；无证据保持未知，不发假消息、不唤醒模型验收。
- social.update 保留 dryRun 默认预览，显式 dryRun:false 应用；移除无条件第二次精确“确认”口令。保留 admin/cross-agent、channelInstances 与已授权目标；核验直接主人群/私聊、可信 parent_ask/原生续办来源。非主人、来源不明不能提权。

## B 授权与委派契约

- parent_ask 回溯真实入站、batch 及 runtime.tool-result/runtime.continuation 的 parent；逐跳核验 agent/session/conv、内部事件、防环上限。旧批次兼容，混批逐一核验非主人额度。
- 来源缺失/伪造明确 origin 错误，不静默降为 guest 后报外人额度；准入拒绝使用已有 error/reason/isError，不把 done 当目标成功。
- effort/credentialSlots 可选覆盖错误指出参数、required/current capability 及合法省略覆盖路径；不自动提权、不暗丢用户必需参数、不原样无限重试。
- agent_ask.sources 仅逐字引用，不等同跨 Agent 主人授权；不扩大 peer 权限。parent_ask 来源延续与跨 Agent 委派分开。

## C 运行事实与附件契约

- 每次原生模型请求在稳定前缀后追加独立事实段：配置首选、本请求实际 provider/model/thinking；fallback 随实际选择更新。不从当前 YAML 猜历史模型；供应商响应型号只取真实观测。
- 附件行给 message/index；本轮有 conversation_attachment_read 时指明受限入口。复用作用域/下载/文本读取，不开放整个 home、不造新工具、不声称读懂未解析二进制。
- 复用当前已有群参与、addressedTo、公开背景和发送控制，不新增判断模型或自然语言状态机。系统和 self-management skill 只补公共操作闭环，不写 Bot 特例。

## 验收、分工与交付

回归覆盖目标 profile 模型更新、不可运行路由写前拒绝且旧状态有效、reload 失败恢复；主人经 batch/续办仍为主人，访客/混批/伪造不升权；可选 effort 拒绝与普通委派区分；附件引用可读而越会话/任意路径拒绝；实际 fallback 与配置首选区分；mute 有真实策略与发送控制。

执行 build/typecheck/npm test/lint，保留原始通过/失败/跳过。真实模型仅 openai/gpt-6-luna；缺测试环境凭据标未测，不复制其他应用 OAuth。源码、真实模型、QQ/飞书、正式安装分别记录。结果写 docs/verification/harness-self-configuration-20261101.md，本方案不是已实现声明。

早期 config_routing、delegation_auth 等子任务已完成对应源码阶段；当前 Luna 子Agent负责共享默认/消费者修复与正式发布、本机更新，主Agent维护规范、公共指引、差异图并执行集成验收。全部共享main，不建开发worktree；用户已明确授权正式发版更新与真实飞书/QQ群测试。配置须由实际Agent依原话自行完成，不预配目标群伪造通过，失败候选恢复保留原件与备份。


## 2026-11-01 补充：完整默认链与自然语言验收

主人进一步要求：按群类型、渠道与接入方式给出完整默认值；错误让 Agent 知道怎样补齐整个依赖链；用户与验收输入都采用实际飞书/QQ口语，不能借 user message 教模型配置步骤。上一轮英文操作式 live test 仅证明“按明确步骤调用现有 CLI”，不证明自然需求可用，历史证据保留但降低结论范围。

### 默认值分层与优先级

显式拒绝/禁用/隔离 > 已有自定义绑定、profile、所选策略 > 渠道已确认的接入事实 > 官方安全默认。用途来自主人的明确需求，群名称/昵称/普通正文不能自动形成权限或新接入范围。沿已有模型/账号/窗口值补齐，用户没指定时不发明统一模型、秒数或主动权限。

| 场景 | 采用的默认链 | 无法确定时 |
|---|---|---|
| 已识别主人私聊 | 既有 owner/main 绑定及主 profile，自动最终投递；模型改动只定位该 profile | 未关联账号先指出真实身份映射缺口，不把首个发言者当主人 |
| 访客私聊 | 沿渠道已有准入和独立受限上下文；Card 使用已实现访客链 | 未授权渠道不自动接入访客，不把访客送进 main |
| Card/membership 已确认入群 | 同 Agent 独立 per-conv 群上下文、受限群工具、social 参与、显式发送、必要时 parent_ask | 只认平台 target/membership，不从名字推断入群 |
| 官方 QQ 新接入 | 复用 setup 的扫码主人 DM、独立群档、群记录、social 批次和主协助链；对已准入且所选插件已加载的官方安全群绑定，缺省批次可沿现有派生机制补齐 | 平台全量接收/主动发送授权缺口要明确反馈，不能假装宿主能补平台权限 |
| 旧 QQ 官方链 | 沿既有 preview/backup/幂等迁移；只补可证明的官方链缺件，保留自定义结构与显式禁用 | 不把“跳过/部分迁移”报告成全链完成 |
| 飞书显式群接入 | 按实际 allowedChats/身份/已选绑定和独立群上下文配置；完整操作知识随包可查 | 尚无可信 membership 默认，不自动把任意群分给所有 Agent；缺接入关系时给出需补的具体对象 |
| 主人说“这个群都看着，不一定回” | 接收/入账与模型唤醒、公开回复分开；沿实际可用的群策略设置，保留模型对是否回复的判断 | 自主合批需要明确意图后才启用，不改无指令的普通群默认 |
| 同 Agent 跨会话协助 | 新建非 isolated Agent 有可用 main 时生成精确 parent-request→自身 main 的默认入口，沿主 profile，保留真实原授权 | 已有自定义 parent 路由或无 main 时不覆盖，错误指明对象与校验路径 |

默认派生只补已获准范围内的机械缺件，不隐式安装插件、添加渠道、提升群权限或共享私人主会话。若必须重启、外部授权或缺模型/凭据，返回真实缺口，已完成的配置与未完成接入分别报告。

### 工具错误与宿主知识

沿现有错误/ConfigIssue/回执格式提供：具体对象及字段、拒绝原因、缺失依赖、现有可执行修复入口、重新校验与读回方式。插件加载、profile 选用、批次绑定、main 协助是不同依赖，错误按实际缺件说明，不只给“无权限/没有绑定”。权限拒绝不建议绕过/提升 level，缺身份不能靠模型自述补齐。

管理知识来自共同底座、工具说明、随包 self-management skill/docs 和可信本轮事实。宿主按实际安装给可用的本机 CLI/Node/home 定位；远程执行环境不能把宿主路径当可执行路径。不靠用户提供文件名、CLI位置、候选文件或操作顺序，也不强制为管理需求自动加载未选 skill。

### 自然验收标准

新增自然需求场景，user message 只放主人原话或明确标记的同风格改写，例如“你把自己的私聊主模型切换成 sonnet 5.5，群聊默认还是 terra 就行了，我们私聊用 sonnet”和“首先，第一个需求就是把这个群改成你是每条消息都能够接收……接收了不一定要回复”。不得含 CLI 路径、home/候选/回执文件路径、工具名、操作步骤、完成标记或如何调用的指令。

测试环境在消息外正常接入渠道、映射身份并提供真实事件元数据；产品通用系统/工具/skill 不因场景加答案。只用真实 openai/gpt-6-luna 执行测试。其他目标模型必须来自真实被测目录；目录不具备或缺授权是合法阻塞，不能造模型目录制造通过。实际配置结果/热接纳/新路由/送达与保留未涉及字段由宿主外部断言，不规定 shell 拼法或自然语言回复格式。协议回放和真实客户端分别记录，不把 CLI 假装成 QQ/飞书。


### 自主批次不能被二次硬规则吞掉

复核真实调用链发现：参与配置能给出 batch.run:true，定时器也接受，但群发言协调仍可因关键词/关注未命中、count 未满而推进旁观游标，不让模型判断少量普通消息。修复以现有策略为准：明确授权的普通批次在已有窗口与限制满足后进入模型；默认 run:false、明确拒绝/静音/quiet、他人明确接单与机器人互刷限制保留。不新增自然语言正则，也不把“收到了”当作“模型已看过”。工具/skill 同时解释 intake、mode、batch.run 三者，避免让模型根据 user message 中的技术提示才能配置。

自然群取证发现：主会话正确收到 private profile，却把未指定 --profile 的 inspect 默认 group 权限结果误认为当前权限，又调用仅非主会话可用的 parent_ask。共享修复保持 CLI 兼容默认，明确检查对象；主会话不提供不可执行的 parent_ask，通用委派语义明确接办和内部回传。验收环境恢复真实默认技能发现，不能通过关闭管理知识测试后给用户补操作提示。

进一步重复验收中，即使通用管理技能已可读，裸inspect默认对象误判仍复现；一次成功不足以交付。修复提升至执行边界：仅本机Agent进程中的只读inspect，在实际home匹配且无显式覆盖时沿当前Agent/profile；显式参数和跨home/Agent边界优先，普通终端及配置写入默认不变。环境上下文只定位、不授权，避免再靠用户message或提示词保证不丢当前对象。

目标与原文也须由宿主正确呈现。主人私有main的已绑定、已观测群摘要，可由Channel精确查询该会话的平台显示名；未知显式标注，名称不构成成员资格或授权。`parent_ask`的全部原始来源核验为主人后，以完整有序原文作为主目标，分身转述只作辅助，不能覆盖原话中的行动、验收或发送要求；混合来源、访客、未知来源沿既有限制。复用现有摘要预算与来源核验，不增加意图分类器、任务数据库或第二个决策模型。


### 2026-11-02 真实复验后的执行约束

v7已证明原生配置、校验和热重载可由Agent独立完成，但完整群需求仍失败。默认派生误用后置同渠道observer证明前置精确自定义来源，覆盖了真实首匹配语义；随后缺当前群消费者却只入账。参与候选、策略和路由须复用真实顺序匹配结果，消费者按当前事件、插件、conv、profile与会话key证明，不能拿别群消费者放行。已获准profile的机械伴随绑定复用现有机制；不自动为profile增权。群独立上下文与main管理/交付责任可以共存，共享指引必须说清，不能因私人main绑定受限就放弃可行工作。原话、源码检查、正式发布、真实入站/运行/送达分层证据见本轮verification与私有原文导出。


### 本轮实测补齐的公共约束

当前原话不能淹没在平台补充历史中。输入统一为宿主事实→补充背景→原事件正文/verified owner任务区；原文最后且只一次，JSON文本保留引号但保持围栏安全。私有main沿既有event ID说明当前请求与历史完成证据的边界；原生重放按平台ID去重，不把不同事件的同文请求当重放。历史回执只证明其来源，当前原话仍决定是否需要新动作，不强制重放已完成副作用。

群模型处理与公开发言机会分开。群会话无当前机会时保留协调限制；若未完成原任务需要交付，错误按真实可用工具指向已有parent_ask→所属main按核验原件和原群目标继续。缺工具/main/发送权限如实报未投递，暂停和已可靠回应不建议绕过；不新增lease或队列。主会话可直接完成已有权限内的原群交付，不强迫受限群会话再次发送而被同一门拒绝。

发版、安装与Cloud各有证据：候选CI、tag门禁、资产、产品原生updater回执和实际进程分别核对；Cloud实际build-version及/work工作RPC另验。Release的派发步骤success可能只是缺CLOUD_DISPATCH_TOKEN而记web-pending-reconcile，不能当网页已部署；不同产品版本号也不直接证明workProtocol不兼容。当前Cloud已恢复可用，历史那次中断原因仍未知。

自然模型测试保留失败/跳过和正确检查对象。所有当前源测试排除.cache副本；配置成功不代表普通消息进入模型，run done不代表群已投递。缺少生命周期证据时，只增强既有测试的有界白名单诊断再复测，不改原话、成功断言或超时来换通过，不启用完整provider正文/秘密trace。真实飞书/QQ仍是最终验收。


后台结果与历史正文还需明确证据类型。runtime.tool-result/continuation复用当前真实会话和requestSources核父链，只给有限原请求ID/conv与total/omitted，无法核验即unknown；报告不是新主人指令，也不能证明后来输入已完成，不复制原件/结果正文、不自动fan-out。飞书背景按native ID去掉当前pending正文副本，保留不同ID的同文历史；已送达助手叙述保留原parent和记录时刻，回执只证送达、不把内容自述升级为当前配置事实。原始来源、实时有效状态和实际投递分别作为证据，模型据当前目标决策，而非由第二个模型或新账本裁决完成。
