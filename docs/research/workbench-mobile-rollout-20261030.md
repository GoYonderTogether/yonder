# 工作入口与手机个人抽屉：分阶段交付

2026-10-30。主人在本聊天批准既定设计，并要求 Terra 并行/顺序实现、先发布前端预览，再继续接通后端。此记录只管理本轮范围，不替代现有安全规范。

## 已批准的前端行为

- 桌面导航依次为消息、工作、市场、通讯录，个人头像留在底部。
- 手机底部四项依次为消息、工作、市场、通讯录；个人入口移至一级页左上角头像，点击后从左侧滑入个人抽屉。
- 头像不占用聊天、任务、个人详情的返回位置。抽屉复用现有个人资源入口，复杂页面仍独立打开；保持草稿、滚动与当前会话。
- 抽屉具备遮罩、关闭按钮、键盘关闭、焦点管理、滚动锁与减少动画支持。边缘打开/抽屉滑动关闭不取代按钮，不截断纵向滚动。
- 云端无工作台连接时仍能进入“工作”，真实说明安装/连接方式；不展示虚构任务、设备、在线态或已获得的权限。
- Card 消息接入和 Gateway 工作授权分别表述；云账号登录不自动成为本机 owner。
- 第一版先验收云端实际网页；本机无社交服务的工作入口继续可用，不为凑四项导航引入无效社交页面。

## 执行与验收

1. Terra A 负责 Shell、个人抽屉及一级页头像；Terra B 负责工作入口和真实空状态；Terra C 先只读梳理后端安全契约。
2. 第一阶段完成必要检查、真实手机/桌面浏览器验收并发布前端预览，向主人发送原网址与截图。只改本轮路径，不提交其他 Agent 的改动。
3. 第二阶段在第一阶段上线后开始代码落地，优先使用已有 Gateway 鉴权、RPC、事件流与同一会话来源；不复制转录，不把社交 DM 自动提升为主人会话，不把执行设备 relay 当作工作台 relay。
4. 需要新增云配对/授权公共契约时先列缺口交维护者，不用假状态、宽权限或测试码补洞。已有直连接口范围内的接入与读写继续实施并实测。

## 第二阶段已确认的最小范围

现有 Gateway HTTP RPC/WS 协议可用于显式地址与访问令牌登录；本轮先接通此路径，不增加云账号自动配对或新的控制中继公共协议。用户自行选择目标设备；不自动发现浏览器本机地址，不把 /console 当作已授权个人设备，不修改 remoteOwner/remoteAdmin。

- 添加/保存设备仅保存 id/name/origin；长期令牌只用于换 HttpOnly 会话，旧本机存储中的 token 不继续保留。
- 工作区的 RPC、WS、查询和输入必须指向同一已选设备；切换设备时清理旧连接/订阅并重建按设备隔离的工作树，不复用旧会话 ID。
- 输入草稿按设备及会话隔离；在途操作固定提交时的设备，切换后不将旧操作结果投射到新设备。
- 云工作入口提供实际地址/授权接入，成功后读真实会话；离线、鉴权失败、owner/admin 权限不足分别如实显示，不放宽 CORS 或既有 scope。
- 验收使用真实 Gateway 的任务/会话读取、创建/提交/取消及切换隔离；云账号自动关联/中继缺失仍保留未完成，不冒充已上线。
