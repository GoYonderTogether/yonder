## P0 检查待处理输入与上下文区间

- **作业**：用原生飞书入口追踪迟到消息，核对消息ID/原始时间、接纳事件、运行成员、背景区间及成功投递；确认已处理旧消息没有再次作为待处理输入。群内插话作为背景，不拼成当前用户指令。
- **改动边界**：只有证实实现偏离D36时，才修改 `plugins/channel-feishu/src/` 的历史/上下文与 `packages/core/src/runtime/`、`packages/core/src/sessions/` 的共享调用点；不加第二转录、年龄过滤、自动丢弃或新队列。
- **交付**：保留原生输入→模型请求→输出的关联，列清一次接纳/一次消费/渠道送达。模型已正确获得历史仍选择回应旧问候时，记录为行为/设计待议，不冒充重复接纳缺陷。
- **停止条件**：区间和消费事实正确，原生迟到/已处理/多人穿插场景有证据；发现规范空白则列出，不自行定语义。

## P2 打磨安装、TUI与内置skills

- **改动边界**：`packages/cli/`、既有安装/服务脚本及 `skills/skill-creator/`、`skills/yonder-development/` 的当前说明；如必须动共享实现由主agent处理。保留pi原生交互，不新增客户端或安装管理系统，不把PyYAML未就绪写成已通过。
- **交付**：隔离新home的首次安装/登录证据与正式home的只读/经批准更新证据分开。真实系统注销/登录由用户协调后验证，不能用进程重启代替。正式进程始终一个。

## 顺序与可并行边界

P0先收敛上下文事实，再执行依赖它的P1；P2与P3可分路。P4复用已有证据，最后P5汇总。执行时若仍采用三路agent：一支飞书、一支浏览器/桌面/Web、一支CLI/安装/skills；核心、SDK、共享配置、权限与结果总账由主agent独占。用户已批准Sol/Luna分路：Sol负责飞书，Sol负责浏览器/桌面/Web，Luna负责CLI/安装/skills；主agent独占core/SDK/共享和结果总账。固定短脚本与隔离会话优先，多群可并行，UI按目标串行避免争抢。

## 已有实现问题与设计待议的分界

- **已知验收缺口**：真实steer、飞书完整矩阵、新用户安装、完整TUI、CUA已记录失败、creator脚本依赖、可选插件开发闭环；不能都改称确定的源码bug。
- **已证实历史实现问题**：C轮审查缺陷及R/F修复保留在原结果；本轮不因历史曾失败就重新标为未修复。
- **设计/上游待议**：平台迟到或不可枚举消息、LLM是否主动回应旧问候、CUA宿主资源生命周期等，先以P0/P3事实定位；只有现有契约不能表达目标才另提最小设计修订。
