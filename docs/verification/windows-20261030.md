# Windows 桌面补齐与验收（2026-10-30）

维护者要求解释并处理上一轮剩余失败，补齐 Windows 对应桌面能力，验证真实模型、TUI 与整机重启。沿用单一 pi 运行/转录、SDK 插件、能力和可信 owner 边界；没有修改 vendored pi 或发布远端版本。

## 失败原因及处理

- 上轮 69 项包含 Windows 合成 mode 与 POSIX 0600/0700 的错误比较；已改为真实 ACL，并把渠道凭据、交互端点、clipboard 和 Hermes 写入改为保护空文件后再写字节。新增真实 ACL 宽授权、硬链接、符号链接、拒绝覆盖检查。
- Unix 路径分隔符、/System 音频、/usr/bin/openssl、shebang 执行和 macOS transport fixture 写死导致跨平台失败；已按系统路径/解释器/原平台协议纠正，未用整批跳过掩盖。外部 BrowserSkill daemon 本身仍为 macOS，Windows 使用实际验证的独立 Playwright 驱动。
- Node 在 Windows 忽略 O_NOFOLLOW 的路径实际接受过符号链接；Hermes/clipboard 增加 lstat 拒绝，保留原非普通文件/大小检查。
- 原 macOS launchd 调度和桌面硬拒绝 Windows；已分别提供真实计划任务与 Win32/UI Automation 实现。Windows 不伪造 TCC grant，电源租约不修改全局电源计划或覆盖强制休眠。
- 本轮真实计划任务发现 `-WindowStyle Hidden` 使无依赖 PowerShell 标记任务持续 Running、不执行；同一最小任务去掉该选项退出 0，直接 Node 任务也退出 0。服务 bootstrap 改用 .NET CreateNoWindow 启动 Node，不依赖模块 autoload；服务子进程仍 windowsHide。修复后全服务链和托盘回执通过。
- 桌面专项早期只得到根窗口/通用 Pane，随后显示专用 WinForms 窗口并按真实 UIA 控件和 bounds 验证。首次 SendInput 断言早于 UI 消费全部字符；改为等待真实窗口写回一致字节，未把 API 接纳等同于文字已呈现。
- 沙箱创建的仓库内 home 拒绝 DACL 修改，保留安全失败。真实部署验收使用当前用户 AppData 私有 home，不放宽 ACL。
