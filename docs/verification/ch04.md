## 飞书看板重复请求调查

旧 `task-card.ts` 每两秒读取本地看板，内容变化时 PATCH 原卡；每次显式 `showBoard` 则发送新卡。该旧路径已在 `da0cb91` 移除，现有 `tasks_show` 发送 PNG。只读检查 y_events 时，含 `data.msgId` 的飞书入站事件按会话及消息 ID 分组没有重复；`task-card-updated` 两条属于不同来源消息和卡片。这些证据不能确定主人观察到的重复回复根因，也不能证明所有事件均未重复。

## 主人真实渠道实测

1. 在已授权的飞书私聊发一次“显示任务看板”，记录时间和入站消息 ID，确认收到的看板消息数量。
2. 只变更一次任务状态，观察是否产生额外的新消息，并记录飞书消息 ID 和时间。
3. 如重复，按同一入站消息 ID 对照该运行的 `message.in`、`message.attempt`、`message.out` 和 `channel-feishu.task-card-updated` 事件的 parent、`data.msgId` 与平台消息 ID，区分独立工具调用、投递重试和平台重复投递；保留时间与 ID，不需要提供聊天原文。
