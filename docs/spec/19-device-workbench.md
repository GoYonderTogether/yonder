# 19 · 一次设备授权的工作台

2026-10-30 主人明确批准：Yonder 是一个产品，设备授权统一包含消息与工作访问；网页不再要求第二次 Gateway 地址/令牌登录。本节替代本轮先前“单独授权工作台”的产品行为，不改变普通社交消息的权限。

## 1. 身份与权限

- 复用 16 §1 已有设备绑定：网页 human 账号、devices.owner_id、设备 origin 绑定的 deviceToken 及 /ws/device。已绑定设备不再新增确认、密码或第二份长期凭据。
- 网页浏览器只使用既有云账号 HttpOnly 会话；deviceToken、Gateway token 不进入网页。云端逐次验证当前 web session、设备所有权及设备会话仍有效。
- 设备端将已认证控制帧的 ownerId 与本实例已核实的主人关联再次核对。账号与任何相关 Agent 的配置 owner 冲突时拒绝，不因“某一个 Agent 匹配”获得整个实例控制权。
- 工作控制只经专用控制帧进入现有 registry，固定 read/write/owner；admin 与 local:true 继续禁止。普通 DM、群消息及非主人账号不得进入此路径，客户端不得指定 principal 或 scope。
- 此版本信任已部署的云端经 TLS 转交主人请求，云端技术上可读控制正文；不宣称端到端加密。沿用现有撤销和真实设备连接，不另建授权平台。

## 2. 网页接口与设备状态

- GET /api/devices 继续返回原有设备字段，增量可选 workProtocol: 1；仅当前有效设备连接主动宣告支持 v1 时存在。online 不等于支持工作台。旧设备仍可消息连接，并提示更新。
- GET /api/devices/:id/agents：仅设备主人可读取已绑定设备未退役的 `{key, actor}` 映射，actor 与联系人使用同一账号资料；其他账号和解绑设备返回 404，设备凭据不能访问。
- POST /api/devices/:id/work/rpc/:method：现有 human 会话，正文为 registry 原 params；响应沿用网关 {ok:true,result} 或 {ok:false,error:{code,message}}。方法/参数仍由设备 registry 校验。
- WS /ws/work?device=<UUID>：只允许本站 Origin 与有效 human 会话。浏览器帧沿用已有 Gateway sub/unsub/ping 与 ready/ev/end/pong，不新增第二套前端流协议。
- 不属于当前账号的目标返回不泄露存在性的拒绝；离线为 device_offline；在线但无 v1 为 work_unsupported；未核实设备主人为 forbidden。HTTP 失败状态与 JSON 错误保持一致。
- 控制请求超时为 outcome_unknown，不伪装为已执行或未执行，不自动重发副作用；正常用户主动重试沿原 requestId 幂等语义。

## 3. 设备通道

- 设备 hello 增量宣告 workProtocol:1；未准备好控制宿主或主人核对失败时不宣告。
- 设备令牌调用既有 GET /api/session 时，响应在 actor 外增量返回 deviceId；网页会话形状不变。插件据此固定本连接的设备身份，拒绝控制帧中的不同 deviceId，不从社交发送者或任意客户端输入推断设备归属。
- 云端为工作连接生成不可由客户端选择的 channelId，RPC 生成 requestId，分别绑定浏览器 session、ownerId、deviceId 与具体设备 WebSocket。一个设备有多个连接时只固定一个支持 v1 的实际 peer；不广播控制请求。
- RPC 下行 work.request 携带 requestId/ownerId/deviceId/method/params；上行 work.response 只接纳原 peer 与待处理请求，携带 requestId、ok、result 或 error。断开后的迟到回复不跨连接投递。
- 流下行 work.open / work.frame / work.close 携带 channelId 与已核实 ownerId/deviceId；frame 为原 Gateway 客户端帧。上行 work.event 携带 channelId/frame，frame 为原服务端帧。云端不允许设备向任意浏览器指定目标。
- 初版工作桥每次重新订阅从真实当前快照开始，ready.gap=true；不承诺持久游标补收，不建立新转录副本。会话内容、运行和事件仍属于原内核，复用已有网关快照/流适配逻辑。
- 每个连接的订阅和在途操作绑定 AbortSignal；网页退出、设备断线、注销、解绑取消订阅并关闭通道。取消传输不等于撤销已提交的模型任务；真正中止仍调用 sessions.abort。
- 云端请求和事件转发前复核会话和所有权；空闲连接最多 5 秒复核一次到期/撤销。显式解绑通过当前 Hub 主动断开，不声称跨进程无延迟失效。

## 4. 宿主与 SDK

- ChannelIO 增量可选 control 接口，仅已获宿主支持的 channel-card 实例可用；插件不可 import core 或 Gateway 内部包。
- control 仅接纳所属 channel 的账号 ref、method/params、AbortSignal 和事件回调；principal/scopes 不可由插件帧或模型填写。core 负责核对账号身份与实例主人并创建固定权限主体，复用 registry.prepareCall/call。
- 实际最小 SDK 形状为 ready(ownerId):Promise<boolean>、request(ownerId,method,params,signal)、open(ownerId,send,signal)；ownerId 是该设备会话 /api/session 校验的云账号 UUID，由 core 构造所属实例各 Agent 的 acct ref 并逐一核验。ready 也必须做此核验，所有未归档 Agent 的 owner 均须非空且一致；无可核验 Agent 不宣告工作能力。流的每个输入帧及输出事件重新核验，失权终止。
- HostCtx 在内核启动返回后才完备，采用内部延迟注册控制宿主；准备前返回不可用且不宣告 workProtocol。不得伪造 release/awake 等宿主事实。
- Gateway 共享的快照/流适配在宿主层复用；不在插件复制第二套运行时，不为桥改变本机和原直连 Gateway 权限。

## 5. 统一入口与撤销

- 工作列表局部标题区的设备筛选始终列出账号已绑定的真实设备及“全部设备”；离线设备仍可见并标明状态，不展示尚无事实的云环境。全部设备按设备分别查询真实工作和 Bot，失败、离线与不支持分别显示；选择一条会话后只连接其所属设备。列表不显示更多菜单；会话更多菜单固定在会话内容区右上角，仅包含当前会话操作。工作全局设置归个人设置，旧工作设置链接跳转统一设置入口；面板收放和返回操作保持可达。
- 云端会话路由、草稿、布局和查询隔离使用账号、设备和会话的复合身份；不同设备的同号会话不能相互覆盖。详情与副作用只由选中会话的设备处理，设备切换先取消旧订阅，旧设备缓存不得作为新设备数据呈现。
- 工作区左侧列表与右侧信息栏均有收起和恢复入口，包括设置、缺失会话及既有独显状态。按账号、设备、会话保存面板意图；断点只推导可见布局，不改写用户意图。设备选择只显示当前设备名的菜单按钮，移除布局下拉，更多菜单提供恢复默认视图及真实次要操作。桌面最多三列、平板最多两列、手机一列；自动布局中有内容的右栏优先，用户手动展开列表时右栏暂时让位。点击当前列表项也进入正文。
- 右栏数据区分加载、错误、确认空和有内容：加载或错误不清除已选右栏，确认空时自动布局不占位；用户可主动打开技术信息。异步内容不得抢走已手动选择或正在输入的正文。渠道及子会话面板是右栏内容，共享列数限制；独显右栏时浮窗仍可访问。设置等非会话页面不自动显示会话右栏。
- /work 默认读取当前云账号真实设备列表；有一个可用设备时可直接进入，有多个时按 deviceId 选择。选择和缓存按账号及设备隔离，切换取消旧流，不串会话及草稿。
- 设备离线不卸载已加载的工作内容：浏览器缓存当前账号、设备的真实 Agent、会话列表及已访问会话的已加载上下文窗口，同一浏览器标签刷新可恢复；不预拉未访问的全部历史，不保存令牌或另建服务端转录。离线展示须标明离线或缓存状态，不将旧运行状态当作实时事实；发送、修改等副作用仍须真实在线授权，恢复连接不重放副作用，沿已有快照与查询刷新同步。退出清理该账号缓存，切换账号不能读到旧账号内容；在线权威结果确认删除、解绑或失权时清除对应缓存。断线期间尚不能确认的设备本地删除待恢复同步处理，不以离线推断删除。
- 无设备复用现有 /connect 与 /get；离线显示真实离线；老版本显示更新要求。移除主流程中的地址、令牌和“单独授权”表单。底部四栏和 QQ 式全屏个人页保留。
- 已确认退役的 Bot 与已解绑设备的 Bot 不出现在联系人、私人 DM、工作普通列表及群当前成员/可选 Bot；离线或手动停用不是删除，群本身与历史消息、作者资料保留。设备离线期间发生的本地删除须等下次设备同步才能确认。
- DELETE /api/devices/:id 仅设备主人可用，撤销设备 sessions、停止该设备控制连接，停用其 Agent。保留设备/账号/消息历史，不以删除历史记录实现解绑。后续旧 token 和旧工作连接立即被拒；重新连接沿现有邀请码流程。
- 验收必须包含：一次绑定后直接访问真实工作会话；跨账号拒绝；消息连接不受工作订阅影响；断线不重放 mutation；解绑后的 HTTP/WS 访问拒绝；scope/local 禁止；旧客户端未宣告时可用消息但工作不可用。

## 6. 聊天消息呈现（2026-10-30 主人要求）

- 聊天列表的 Agent 标签为 `bot`；他人的 Bot 在真实主人名称可用时显示“某某的 bot”。不按 Bot 名称猜主人。
- 主人的设备 Bot 私聊可经既有主人工作桥呈现其真实主会话，与工作页共享转录组件；他人的 Bot、普通私聊与群聊沿用社交权限，不取得设备会话访问权。不复制主会话转录到社交存储。
- 消息操作复用桌面右键、触屏长按与键盘菜单；引用不常驻气泡下方。整行悬停或键盘焦点时显示发送时间，预留位置避免布局跳动。跨天或相邻消息间隔至少五分钟插入时间分隔，系统通知保留独立呈现。非主人输入与系统触发输入应与主人输入可区分。
- 渠道信息以不改变气泡排列的角标呈现，悬停、聚焦或触屏可查真实渠道名称、会话名称及标识并复制；没有记录的名称或群号不猜测。
- `TranscriptItem` 增量提供可选 `timestamp?: number`（毫秒）、`target?: number`（准备编辑指向的条目 ID）及 `prepared?: string`（该编辑真实用户输入文本）：从 pi-durable 已有条目及准备编辑中投影，不新增转录存储、不修改原 `text`、`kind` 或模型输入。仅识别内核实际产生的固定包装；正文不显示该元数据，详情按原插入顺序和位置在气泡上方浮层显示，不挤动消息列表。未返回的信息不得伪造，普通用户 XML 正文不得当注入删除。QQ 的真实会话 OpenID 不等于群号，不以“群号”标注。
- 消息历史按游标滚动拉取，并限制同时保留的数据和渲染节点；卸载后可重新获取，加载更早消息保持阅读位置，新消息不强制打断历史阅读。社交服务分页为可选增量参数，原 `since` 同步语义保持兼容。

## 7. 运行位置、资源工作区与模型（2026-11-02 主人批准实施）

用户选择两个独立目标：Bot/会话的运行位置，以及它工作的设备/目录资源集合。运行位置是实际 Harness，云端或已连接设备；会话转录仍只由该宿主 pi-durable 管理。切换查看端不迁移会话，已有会话不通过下拉框暗中迁移；新建会话在所选宿主创建。Bot 部署、启动、停止属于明确的管理动作，不把社交 Bot 账号当运行实例。

- 工作区可以多选设备、多选每台设备上的目录，或者仅选设备。未指定目标时沿用该 Bot 已获授权的资源集合，并能查看它可控制的设备；不表示授予整个账号所有设备。显式选择只收窄执行目标，实际执行须核对当前资源集合与设备 grant，不以提示词代替授权。额外设备经 devices 工具调用，一次运行仍有一个默认 ExecutionEnv；远程默认目录经实际环境适配访问。目录选择约束文件工具和默认执行目标，不把 cwd 当成任意 shell 的安全沙箱；exec 能力与操作系统隔离仍按 05 执行。
- 资源表达为 `{deviceId,paths:string[]}[]`；`deviceId: 'local'` 指当前运行宿主，其他 ID 为执行协议 UUID，和云端账号设备 UUID 显式映射，不能混用。空集合表示未指定；某项 paths 为空表示仅选该设备，仍受实际 grant 限制。目录和设备状态来自真实查询，不创建展示用设备或默认目录。
- 模型列表只有云端提供的模型和当前运行宿主本机配置的模型。别的设备上的模型不因设备在线而可用。不自动上传本机 auth/OAuth 文件；云端 BYOK 为用户明确配置，官方订阅模型只有真实配置和权益可用时展示。本轮不实现支付或虚构订阅权益。
- 模型引用沿用 `provider/model`，目录附带 `source: 'runtime'|'cloud'`、供应商名称、模态与支持的 effort。云模型须接入宿主实际模型解析与调用链，不只在网页拼目录。选择模型和 effort 默认只影响当前会话，下一次运行生效；运行快照和恢复规则沿用 07/10。
- 主人工作台新建默认显式选择 bypass；readonly、standard 与用户自定义权限预设复用 05 的能力集合和已有 preset 的 level/capabilities。仅 owner 管理入口可修改会话覆盖。已有 Bot 会话可设置工作选项，但 permission/resources 覆盖只应用于经可信主人控制面接纳的工作台输入运行快照；后续普通渠道输入仍使用原 profile/source 权限，不继承主人 bypass。可信来源由宿主控制面记录，不接受模型或客户端自由填写的身份；在途 steer/followup 不扩大已冻结权限。模型/effort 保留既有会话级语义，Bot 全局 profile 默认另走既有管理接口。普通渠道、群聊和未带覆盖的旧 sessions.open 不因此提权；设备端授权上限始终有效。bypass 不等于跨设备所有权或操作系统沙箱逃逸。
- 输入区保留发送按钮，增加加号选择文件/图片，以及桌面拖放。上传必须落到会话宿主可读的附件存储，再以真实附件引用提交；失败保留输入与待处理附件。浏览器本机路径不能当远程路径。未支持的格式/大小明确报错，模型是否能直接看图按实际模态判断。单附件输入须保留在会话转录投影，刷新仍可见；上传图片可查看，文件可取回。`attachments.get {session,uri}` 仅经 owner 控制面读取真实属于该会话的上传附件，并限制在宿主受管上传目录和大小边界内，返回内容供浏览器生成 Blob；不得把任意 file URI 转成跨设备读文件入口。
- 底部资源入口固定为“运行位置”“工作区”两个按钮，另有“权限”与合并的“供应商 / 模型 / effort”按钮。模型为主要文字，右侧 effort 为次级文字，暗色主题保持对比。模型/权限菜单及多选支持键盘、焦点和窄屏；运行位置显示真实宿主名，不将云站同源称为用户电脑。

共享控制面增量接口：`models.list {}` 返回 providers/models 结构化目录；`workspaces.list {}` 返回当前宿主的可选资源和可用权限预设；`sessions.options.get {id}` 读取会话实际模型/effort/permission/resources 与运行状态；`sessions.options.set {id,model?,effort?,permission?,resources?}` 在 owner 边界校验并持久覆盖。`sessions.open` 可带同形 options，旧调用不变。运行或工具在途时拒绝切换资源；模型/effort 下一轮生效。具体 DTO 由共享实现和对应 schema 单源维护，不在前后端各造一套模型命名。

多设备执行沿已有 devices 插件扩展注册文件/进程动作。选择远程资源可为该运行启用已安装的 devices 能力，不自动安装插件，不扩大设备集合。默认远程目录通过 ExecutionEnv 使用普通文件/进程工具，额外目标通过 `devices_operation` 显式指定设备和操作；注册动作和调用前校验共同按 read/write/exec 收窄，路径 scopeRoots 由受信控制器与 grant 决定，不接受模型自报权限。远程传输不是授予模型任意网络操作能力的理由。子任务继承实际资源及能力上限。

当前远程文件传输每次完整读取上限 512 KiB，超限明确报错。远程 readonly 的 grep/find 通过目录和文件读取实现，不授予 exec；本地 rg/fd 行为不变。远程搜索使用 Node glob 与受限 JavaScript 正则，支持根目录及下级的基础 ignore/negation，不宣称完整 Git ignore 或 Rust regex 兼容；超过读取限额的文件须报告跳过，遍历超过一万项提示收窄范围，正则运行有单文件截止与显式错误，取消停止搜索。产品须如实呈现这些限制。

云端托管沿用同一 Harness，按账号隔离 home、凭据与执行环境；复用实际绑定的 deviceId 与工作桥，由可信安装管理登记 cloud 类型，浏览器不得自报设备为云端。用户可管理实际云端实例，未安装或失败明确显示，不以虚构设备占位。云端网关仅按授权使用用户密钥，密文与解密主密钥分开保管，日志和浏览器响应不得回传明文。自定义 provider 出站须限制云端内网/元数据访问。用户设备主动出站连接中继，支持多条明确源/目标路由，不广播命令；共享已有签名、grant、持久 commandId、取消和 unknown 结果语义。离线不等于取消，未知结果不重放副作用。
