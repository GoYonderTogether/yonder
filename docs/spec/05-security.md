# 05 安全与执行环境

安全只有一层：**能力 + 级别**。没有审批流、没有验收。以后需要审批时写成钩子插件（04 §3.6），不改这一层。

## 1. 能力

固定词表（0.1）：

| 能力 | 允许 |
|---|---|
| `read` | 读自己作用域内的文件与数据（自己的工作区、自己的会话） |
| `write` | 改自己作用域内的文件与数据 |
| `exec` | 在执行环境里运行程序 |
| `network` | 工具发起外部网络请求 |
| `message` | 向当前来源以外的会话发消息（06 §5） |
| `cross-agent` | 读其他 agent 的会话、事件与身份关系 |
| `admin` | 改 `agent.yaml`、身份关联、其他 agent |

扩展词表属于插件 API 变更（04 §6）。

## 2. 级别

级别是能力集合的命名：

| 级别 | 能力 |
|---|---|
| `bypass` | 全部 |
| `standard` | `read` `write` `exec` `network` `message` |
| `readonly` | `read` |

配置档写 `level` 或 `capabilities`（显式列表），二选一。例如：和主人对话的分身用 `bypass`；陌生人用 `readonly`；"只能读公开记忆"由记忆插件按会话能力与数据标注自行实现。

## 3. 工具与判定点

- 每个工具注册时**必须**声明它需要的全部能力。pi-durable 自带工具的映射：`read` → `read`；`write`、`edit` → `write`；`bash` → `exec`。
- **判定点一：提供。** 工具所需能力不全包含在配置档能力内的，不提供给模型，也不能被按需搜索到。
- **判定点二：调用前。** 内核的安全钩子再核一次能力，并检查受保护文件：写 `agent.yaml` 需要 `admin`；插件声明的受保护文件需要其指定能力。被拦下的调用以错误结果返回给模型，说明原因。
- **子会话：** `task_run` 开出的会话能力 = 预设 ∩ 发起方（03 §4）。
- 说明：拥有 `exec` 的配置档可以用命令行改任何文件，受保护文件规则对它没有约束力。真正的隔离靠执行环境（§4），不靠这条规则。文档与 `yonder doctor` 必须如实说明这一点。

## 4. 执行环境

工具在哪里执行由执行环境决定。接口直接使用 pi-durable 的 `ExecutionEnv`：文件读写、目录分页、`exec(argv)`、可选的 `listFiles`。

```yaml
envs:
  local: { type: local }                         # 内置：本机，pi-durable NodeExecutionEnv
  gpu-box: { type: ssh, host: gpu-box }          # 〔0.1 不实现〕插件：基于 pi-env 的远程环境
  sandbox-1: { type: container, image: … }       # 〔0.1 不实现〕插件：容器环境
```

- 配置档的 `env` 选择执行环境；agent 的工作区也位于某个执行环境里（03 §2.1）。
- 主机永远保留：harness 进程、SQLite、凭据。远程环境里只有文件和命令，凭据不下发。
- 执行环境里才有的 agent：工作区只在远程，主机通过执行环境读 `agent.yaml` 与上下文文件。
- 一个配置档在一次运行内只用一个执行环境。

## 5. 明确不在这一层的东西

审批、人工确认、验收、沙箱策略、速率限制。它们需要时以钩子插件或执行环境插件实现。
