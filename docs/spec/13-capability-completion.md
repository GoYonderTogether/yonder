## 2. 核心缺口：在原责任层补齐

### 2.1 运行、恢复与终结

沿用 07/10 与已批准 D28/D29：pi 拥有队列、运行成员、转录和终态原生回执；Yonder 只持久关联事件/会话、运行配置和投递事实。先恢复关联及已结束结果，再启动调度；不能在恢复循环里提前 submit 启动模型。

唯一终结入口负责记录一次 `run.end`、结算等待者、释放活跃资源；投递只负责送达。task 的 `close: manual` 在运行结束后保持可续聊，`run-end` 才自动关闭；保留 U01 的 busy/steer/followup 和终端观察能力。旧 N05 工作树不是整文件替换来源。

### 2.2 子任务、来源和权限

复用既有 `task_run`、`agent_ask`、pi 父子会话与原生工具并行。多个 `task_run` 可并行执行，子结果保留实际身份/状态/原因/附件；父取消沿同一链传播，能力是当前预设与已保存父/调用方上限的交集。能查询父子关联和当前原生状态，不新增批量调度器、任务数据库或脱离父运行的长期子 agent。

插件会话操作的调用来源由 SDK facade/内核绑定，不能让插件通过字符串参数冒充其他来源。事件 parent 表示因果事件，父会话单独表示。运行中合并输入的授权、附件读取和回复目标统一取实际 inputs，不能只看第一条事件。

### 2.3 回执与被动观察

接纳回执返回原事件/会话身份；模型结束回执来自原生运行事实；送达另由 `message.out` 或插件事件表示。观察输出携带可确认的 session、输入事件集合、原生 run/entry/tool 身份和终态；关联身份复用原生值，不另造进度状态机。

TUI、本地控制和 MCP 共用同一被动观察源。连接观察不创建输入、不唤醒模型、不成为 ask 等待者、不抑制正常渠道回复；断开只解除观察，明确 abort 才中止运行。断线后的已落库事实由现有事件/转录查询恢复，不保证补齐每个未持久流式片段。MCP 转发沿用标准通知/进度能力；客户端不能消费时仍可查询原结果，不另开私有常驻任务服务。

### 2.4 配置、附件与原审查遗留

运行开始取一份完整快照；恢复已开始的运行沿用原快照。重载复用启动校验，无效保留旧配置；会话中 profile 不热切换。上限、重复工具停止、版本通知、上下文模板选择继续按 10 §4 与原审查 R1–R10 修在共享入口。

图片不能信任可选 `bytes`：从实际内容确认大小/格式，并使用模型实际支持的输入限制；不能把缺大小当作零。本轮接通已有图片渠道/MCP、CLI 附件参数和子任务附件保留。远程下载结果稳定关联原输入，恢复可找回。新图超限沿用 03 的可读附件提示；已有历史造成超限时明确报告，不删除/截断原转录来伪造满足限制。

CLI 为 `sessions submit` 增加可重复的 `--attachment <本地路径>`，与正文一起转换为既有 `Input.attachments`，保留真实 MIME、大小与原来源权限。TUI 剪贴板图片、拖拽和新媒体编辑器留后续，不因此阻断 CLI/MCP 明确入口。

## 3. 最小管理闭环（已批准新增契约）

所有新增命令遵守 09 的 home、双语帮助、`--json`、错误和退出码规则。它们是同一 CLI 管理面，不另做 Web 控制台、配置数据库或新的插件槽。TUI 只复用已有预设/会话选择，不重做 U05 布局。

### 3.1 插件

| 新增命令 | 固定行为 |
|---|---|
| `plugins list` / `plugins show <id>` | 展示配置来源、包/目录、id/版本、声明与实际加载贡献、被哪些 profile/实例引用；静态清单与运行中实际加载情况分别标注，不把加载称为外部服务就绪 |
| `plugins add <本地目录或已安装包名>` | 复用已有解析/清单/注册校验；完整候选配置通过后原子更新 home 的 yonder.yaml；代码变更明确提示重启；不下载任意 npm/Git 包 |
| `plugins remove <id>` | 移除加载项前列出并拒绝尚存在的渠道/env/profile/preset 等引用；用户先解除引用再移除；不删除外部源码、插件私有数据或运行历史 |

加载项仍以 `yonder.yaml.plugins` 为唯一来源，不增加 enabled 状态表。add/remove 管加载，profile 的原有 plugins/tools/contexts 管选用；不偷偷开启所有 agent，不做热卸载、级联删除或自动服务重启。离线查询必须说明是配置/静态信息，不能声称服务已加载。

候选检查只执行已有 setup 注册与校验，不启动渠道/触发器、不联网；复用现有 loader 的事实和校验，禁止再写一套清单解析器。外部依赖就绪情况沿用各官方插件已有状态入口，不新增通用健康平台。

### 3.2 Skills

保留已有 `yonder skills [--agent <id>] [--profile <name>]` 列表入口，并增加：

| 新增命令 | 固定行为 |
|---|---|
| `skills show <name> [--agent <id>] [--profile <name>]` | 返回按现有优先级解析的内容、来源、选用/遮蔽状态与位置；复用 `skill_view` 的解析/路径规则 |
| `skills add <本地目录> [--agent <id>]` | 读取真实 SKILL.md，复制该 skill 及其附属文件；不带 agent 放 home/skills，带 agent 放该本机 agent 的 workspace/skills；同名目标存在则报错，不覆盖 |
| `skills remove <name> [--agent <id>]` | 只删除明确 home/skills 或所选本机 workspace/skills 下同名直接目录；不跟随链接删除外部文件，不删除插件携带的 skill 或导入来源 |

本轮导入/删除限定本机目录；不假装实现远程执行环境。选择仍使用现有 profile.skills，无第二份启停名单。插件携带的 skill 随插件管理；来源显示 `plugin:<id>`，修复 R10 的目录冒充 id。保留 Agent Skills frontmatter 和资源路径，不另造标准、在线 Hub、自动生成或改进策略。

### 3.3 模型与有效工具配置

- 新增 `models list`：通过现有 runtime 边界读取配置/原生模型目录，不输出凭据，不把目录中存在解释为账号已有访问权。
- 新增 `inspect [--agent <id>] [--profile <name>]`：复用已解析配置和工具注册，显示 model/thinking/env/级别/能力、被选插件/上下文/skills、直接工具与按需工具及未暴露原因；运行中的查询明确区分“下次运行配置”与已有 session 的快照。只输出这些非秘密字段，不输出原始含密钥配置。
- 编辑沿用 YAML → 校验/重载；yonder.yaml 仍需重启。人的任务选择沿用 TUI 既有 preset。没有模型自动路由、自动供应商回退、当前会话 profile/权限热切换或批量配置 CRUD。
