# 17 任务账本（tasks 插件）

官方插件 `@yonder/plugin-tasks`，插件 id `tasks`。只使用 04 的工具、上下文、钩子、触发与事件槽，不运行模型循环，不改内核。设计依据与证据见 `proposals/task-ledger/design.md`、`proposals/goal-mechanism/design.md`。

目标：每个 Agent 的每条任务线都先被记录，状态不靠模型上下文记忆；用户和管家随时能看到全部在办事项；滞留被发现并被推动；“完成”仍由模型自己判定（不变量 6）。

## 1 任务对象

追加式事件存储（插件 data 下 SQLite，只追加，不改旧行）。任务字段：`id`、`ownerAgent`、`session`、`parent`（上级任务 id，sub-agent 的任务挂在发起方任务下）、`title`、`objective`、`acceptance[]`（2–5 条，每条能指向具体证据）、`nonGoals`、`budget{wallMinutes?, wakeups?}`、`state`、`deliverable`、`origin`（来源渠道/会话引用）、`lastActivityAt`。

状态：`open → active → waiting-user | blocked | review → done | cancelled`。进入 `done` 必须带 `deliverable` 与逐条验收证据；这是模型自己写、自己对照的记录，插件不判定“验收通过”。

## 2 工具

`tasks_open`、`tasks_update`、`tasks_done`、`tasks_list`、`tasks_get`、`tasks_show`、`tasks_nudge`。目标机制照搬 Codex `/goal`：持久目标、每次唤醒重现、软预算、完成前对照证据；不照搬 `update_plan` 清单（业界已将其默认关闭）。工具描述文本是唯一的使用指引，不另设上下文文件。

## 3 可见范围

沿用能力模型，不建新权限体系：
- 默认只读写自己的任务；
- 主 Agent 另可读自己 sub-agent（`parent` 链）的任务；
- 持有 `cross-agent` 能力的配置档（管家）可读全部 Agent 进行中的任务，并可调用 `tasks_nudge`。管家不是新角色类型。

`tasks_nudge` 以带来源标记的输入投递到目标 Agent 自己的会话，经其自己的绑定，不绕过任何路由。

## 4 每次唤醒的重现

`placement: turn` 的上下文贡献。任务新建或变更时给完整目标；其余唤醒只给一行：标题、状态、已用时间、唤醒次数、距上次交付的间隔。目标存放在账本里，不依赖转录，压缩后仍在。唤醒次数由插件自数（`RenderContext` 无会话用量，本版不改 SDK）。

## 5 时点机制（moments）

账本在任务生命周期的明确时点上，向 Agent 会话投递一条带来源标记的输入。投递复用现有事件通道，去重、限频，不阻断、不截断。

| 时点 | 做什么 | 默认 |
|---|---|---|
| 滞留 | active 任务超过 N 分钟无进展，且没有后台等待或已接纳的 `task_continue`：提示当前状态，请在继续 / blocked / waiting-user 中选一 | 开 |
| 用户待办 | waiting-user 超过 M 分钟：先由负责该任务的 Agent 自检，仅将确需主人决定的事项纳入提醒汇总 | 开 |
| 完成后压缩 | done 后 15 分钟对该任务所在会话触发一次上下文压缩，经 `sessions.command(id, "compact")` | 关，实验开关 |
| 完成后留存 | done 后 30 分钟内，任务仍在“刚完成”分组，用户再提到时可检索其交付；之后折叠 | 关，实验开关 |
| 完成后复盘 | done 后 15 分钟让 Agent 在隐藏分支整理记忆与技能（复用 hermes-experience） | 〔本版不实现〕：hermes-experience 目前只由轮数计数和 `/refine` 触发，没有外部触发入口；待其暴露入口后补 |

用户待办提醒前，负责该任务的 Agent 使用低成本模型或规则自检：已完成的任务按完成契约关闭；时间相关事项的日期已过则关闭并记账；自己能处理的转为执行；确实需要主人决定的才进入汇总。外发文案由 Agent 改写为“需要你决定：<一句话问题>（选项 A/B）”，最长 120 字，不直接拼接 `waitingFor` 原文或使用内部术语。

新建任务的 `origin`（投递目标）若提供，必须是合法会话引用 `conv:…`；自由文本须报错并提示修正。已有非法目标在提醒时回退到主人的主会话，最多回退一次并记录；失败的投递不按每两小时反复重试。当前每次进入 waiting-user 后最多投递一次自检输入，由负责该任务的 Agent 按自身配置档继续处理。外发汇总仍暂停：改写、旧目标安全回退及通知出口尚未接通；真实模型验证尚未完成。

关闭的时点属于“待验证”：先实现，按 §9 在真实模型上对照，数据支持再默认打开。时点表可扩展，新增时点只加一行。

## 6 展示

原则：**只推送需要人的事**（交付、被卡住、等你、超时），不推送进度噪音；没有变化就不出现。审计里 44% 发给主人的消息是“仍在推进”，展示层不得重蹈。

账本只产出一份 `TaskBoard` JSON，所有渠道都是它的投影，投影里不含任务逻辑。

### 6.1 TaskBoard

分组按“对人的重要性”排序，不按时间：**等你**（waiting-user、review）→ **进行中** → **阻塞** → **刚完成**（完成后 30 分钟内，之后折叠）。每项含：短编号（T1、T2…，在同一人的会话里稳定，方便在聊天里说“T3 先放着”）、标题、状态、执行 Agent、模型、已用时间、距上次进展的时间（滞留标红）、验收进度（met/total）、子任务（`parent` 链）、关联后台任务的输出尾部。

三种视图：
1. **总览**：上述分组列表，顶部一行计数（“2 等你 · 5 进行中 · 1 阻塞”）。
2. **管家视图**：按 Agent 分行，显示每个 Agent 在做什么、是否闲置或滞留；仅持有 `cross-agent` 的配置档可见。
3. **详情**：目标、逐条验收与证据（PR、文件、命令输出）、交付说明、事件时间线（追加式账本免费得到）、子任务树、后台任务输出尾部、来源会话。

### 6.2 各渠道

| 渠道 | 形态 |
|---|---|
| 桌面悬浮窗 | 折叠为计数徽标（“等你”数量突出）；展开为总览面板，可切详情；完成项 30 分钟后折叠。任务看板经控制面视图提供，不含独立 HTTP 服务。 |
| 网页 | 同一面板，含管家视图。 |
| 飞书 | 0.3.x 已退役任务看板卡，任务通知由新的渠道通知策略（`proposals/agent-ux/channels-social.md`，X01）替代。 |
| 微信及不可编辑渠道 | 回复尾部文字清单；用户要看时 `tasks_show` 发图片（SVG 模板 + resvg）；resvg 不可用退化为文字。 |

### 6.3 回复尾部清单与“回来摘要”

`beforeSend` 钩子给面向人的回复程序化追加清单，不经模型。只在存在“等你 / 阻塞 / 新交付”时追加，最多 5 行，等你的排最前；仅有进行中任务且无变化时不追加。用户离开超过 2 小时后的第一条回复，改用“离开期间”形态：完成了什么、等你什么、卡在哪。

### 6.4 回聊天里操作

用户在聊天里说“T3 先放着 / 取消 / 继续”，由 Agent 理解并调用 `tasks_update`；不新增命令解析。停止正在运行的后台任务沿用现有取消接口，本版面板只读，不加停止键，待核对其权限与归属后再加。

### 6.5 Agent 自选呈现位置

`tasks_show({target, view, id?})`：`desktop`、`web`、`channel:<ref>`。Agent 未指定时默认选用户最近活跃的渠道。

### 6.6 分期

P3a（本期）：TaskBoard、总览与详情、文字尾部清单、桌面/网页面板、图片。P3b（后续，数据支持再做）：管家视图、“回来摘要”、后台任务输出尾部（需先核实插件能否读取后台任务日志）。

## 7 配置

插件配置只含：`stallMinutes`、`userWaitMinutes`、`tailDigest`（开/关与行数）、`moments`（实验时点开关）。默认值写入代码，不写示例人设。

## 8 边界

不做硬拦截：不阻止任何工具，不因任务状态拒绝回复，不追加“你确定完成了吗”的轮次。账本保证任务被记录、滞留被发现、用户和管家看得到，不保证模型一定照做。

## 9 验收

构建、类型检查、lint、默认测试通过；真实模型 `openai/gpt-6-luna` 跑 goal-mechanism §7 的场景 2、3 和新增“多任务线并行 + 中途打断”场景（每条件 n ≥ 10，缺凭据标未测）。随后发版，经 MCP 通知生产的 Jarvis 与 Hermes 复盘并录入全部在办事项，核对账本与对话审计一致。完成后复盘 / 留存两个实验时点单独对照，结论写入 status.md。

### 社交通知兼容（CH-01）

启用 social 主动通知出口后，user-wait 产生有稳定任务状态 key 的通知意图，不直接发送；tailDigest 不再附到无关回复。同一任务状态不能同时走旧 moments 和新出口。旧配置仍按旧行为运行；任务事实、board 和手动 nudge 保留。确定性计时不唤醒模型；已有工作继续经原生后台输入接纳。
